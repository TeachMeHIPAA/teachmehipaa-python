# Contributing

## Setup

Install [uv](https://docs.astral.sh/uv/); it provides Python 3.10 or newer
and every tool. Then:

```sh
uv sync                                  # create .venv from uv.lock
uv run ruff check                        # lint
uv run ruff format --check               # formatting, doc samples included
uv run mypy                              # strict type check of src, tests, scripts, examples
uv run pytest                            # unit tests and the doc sample tests
uv run python scripts/generate.py --check  # generated code and reference match the IR
uv build                                 # sdist and wheel, into dist/
```

The contract suite also needs Node.js (for `npx`); see below.

## Generated and hand-written code

The library is a hand-written core plus a resource and model layer generated
from the vendored IR (ADR-0001).

| Path                                                                | Origin                                                          |
| ------------------------------------------------------------------- | --------------------------------------------------------------- |
| `src/teachmehipaa/_core/`, `_client.py`, `_operations.py`           | Hand-written                                                    |
| `src/teachmehipaa/_webhooks.py`, `__init__.py`                      | Hand-written                                                    |
| `src/teachmehipaa/_extensions/`                                     | Hand-written methods added to generated resources (see below)   |
| `src/teachmehipaa/types/`, `src/teachmehipaa/resources/`            | Generated by `scripts/generate.py`; do not edit                 |
| `docs/reference/resources.md`, `docs/reference/code-samples.json`   | Generated by `scripts/generate.py`; do not edit                 |
| `scripts/generate.py`                                               | The generator                                                   |
| `openapi/`, `OPENAPI_VERSION`                                       | Vendored from the monorepo; do not edit (see `openapi/README.md`) |

Every generated file starts with a "Generated from openapi/sdk-ir.json — do
not edit" banner. To change generated code, change the generator, or fix the
IR upstream in the monorepo's `tooling/sdk-ir` and re-vendor it.

A resource that needs a hand-written method, such as `events.tail`, is listed
in `EXTENDED_RESOURCES` in `scripts/generate.py`, with a line for the
Markdown reference in `EXTENSION_DOCS`. The generator then names its
classes `<Name>Base` and `Async<Name>Base` (`EventsBase`), and
`src/teachmehipaa/_extensions/<module>.py` subclasses them under the plain
names (`Events`, `AsyncEvents`), which the clients expose. Add the new method
to `HAND_WRITTEN_METHODS` in `tests/test_generated_surface.py`.

Methods whose IR response kind is `operation` return the hand-written
`Operation` / `AsyncOperation` from `_operations.py` (`wait()`,
`export_result()`). The spec leaves `Operation.response` untyped; to type it
for an operation, add its operationId and a type from `_operations.py` to
`OPERATION_RESPONSES` in `scripts/generate.py`.

## Regenerating from a new IR

1. Rebuild the IR in the monorepo
   (`bun tooling/sdk-ir/bin.ts --spec <spec> --out <dir>`), copy
   `openapi.developer.json`, `sdk-ir.json` and `sdk-ir.schema.json` into
   `openapi/`, and put the IR's `source.release` in `OPENAPI_VERSION`.
2. Run `uv run python scripts/generate.py`. It validates the IR against its
   schema, then rewrites `src/teachmehipaa/types/` and
   `src/teachmehipaa/resources/` (ruff-formatted, deterministic), deleting
   files the IR no longer produces, `docs/reference/resources.md` and
   `docs/reference/code-samples.json`. An IR shape it has no rule for stops
   it with an error rather than a guess, and so does an operation with no
   entry in `SAMPLES` or a required argument with no example value.
3. Run `uv run pytest`. `tests/test_generated_surface.py` fails if any spec
   operation lacks exactly one public method with the expected name; add new
   operations to its `EXPECTED_METHODS`. `generate.py --check` (run in CI)
   fails if the committed output differs from what the generator writes.
4. Run `uv run mypy` and the contract suite, add the new operations to the
   contract suite if they belong to a resource family it doesn't cover yet,
   and add a CHANGELOG entry.

## Tests

| Command                      | What it runs                                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------- |
| `uv run pytest`              | Unit tests: the public clients with a fake transport, webhook vectors, generated coverage, docs   |
| `uv run pytest -m contract`  | Both clients against a Prism mock of `openapi/openapi.developer.json` (needs `npx`)               |
| `uv run pytest -m sandbox`   | Read-only smoke test against the real Sandbox; skipped without credentials                         |

`pyproject.toml` deselects the `contract` and `sandbox` markers by default
(`addopts`), so a plain `pytest` never needs Node or credentials.

Unit tests cross only the seams agreed in the spec: the public client with
`tests/fake_api.py` injected as the `httpx` transport and fake `clock` and
`sleep`, the pure webhook functions, and the generated surface. Take expected
values from the spec, the research docs or worked examples, never from the
code under test. No test calls the live API.

### Doc samples

`tests/test_doc_samples.py` keeps the README and the guides honest. Every
`python` block in `README.md` and `docs/guides/*.md` must follow a
`<!-- sample: <id> -->` line, with ids unique across all of them. The test
type-checks every sample with mypy against the package, using this
repository's mypy settings, and runs each one against `FakeApi`, with every
client the sample creates pointed at the fake (unless it brings its own
`http_client`), then checks what it printed and sent. The Flask, FastAPI
and Django webhook handlers are driven by each framework's own test tooling
with signed Deliveries, on the exact path they were signed for. A sample
that uses `client` without creating it gets the Quickstart's client
prepended. To add a sample, tag it and add a `@runs("<id>")` check; the
test fails if a tagged sample has none. `ruff format` formats the samples
too.

`scripts/generate.py` also writes `docs/reference/code-samples.json`: one
sample per IR operationId, which the monorepo vendors for the language
picker in its API reference. Each operation's entry in `SAMPLES` says how
the sample uses the result; the generator fills in the call from the IR
with the shared example values (`PATH_EXAMPLES`, `KEYWORD_EXAMPLES`) and
ruff-formats it. The same test file type-checks every sample with mypy,
lints it with ruff and checks that it calls its operation's method, so a
sample naming a method the client lacks fails CI. These samples need real
credentials, so they are never run.

The doc sample test also checks that every relative link in the README, the
guides, the docs index, the reference, CONTRIBUTING and `examples/README.md`
points at a file that exists, and at a heading that exists when it has an
anchor.

### Contract suite

`uv run pytest -m contract` starts Prism
(`npx --yes @stoplight/prism-cli@5.16.0`) on a free port from a session
fixture in `tests/contract/conftest.py`, waits until it is listening, and
stops it after the run. `tests/contract/test_contract.py` makes one
representative call per resource family on both the sync and the async
client. The clients use a static token and an explicit `organization_id`,
since Prism can't mock the form-encoded token endpoint. Prism answers a
request that breaks the spec with a 4xx, which fails the call, and the suite
also fails on any request violation Prism reports in its `sl-violations`
header. A harness test checks that a deliberately invalid request is caught.

Prism serves static responses built from the spec's schemas. `--dynamic` and
`--errors` are off on purpose: Prism's own generated responses break the spec
(static strings ignore `pattern`; dynamic numbers break OpenAPI 3.1
`exclusiveMinimum`), so either flag makes valid SDK requests fail. Response
violations are therefore ignored; the suite still checks that each response
reads into its typed model.

### Sandbox smoke test

```sh
TMH_SANDBOX_CLIENT_ID=cli_… TMH_SANDBOX_CLIENT_SECRET=tmh_cs_… uv run pytest -m sandbox
```

It introspects the token, lists Courses and lists Learners in the Sandbox
Environment. It never writes, and CI never runs it.

## Documentation

| Path                          | What it is                                       | Kept in sync by                             |
| ----------------------------- | ------------------------------------------------ | ------------------------------------------- |
| `README.md`                   | Overview, install, quickstart, links             | `tests/test_doc_samples.py`                 |
| `docs/guides/*.md`            | Task guides for partner developers               | `tests/test_doc_samples.py`                 |
| `docs/reference/resources.md` | Every resource and method, from the IR           | `scripts/generate.py --check` (CI)          |
| `docs/reference/code-samples.json` | One sample per operation, for the API reference | `scripts/generate.py --check`, `tests/test_doc_samples.py` |
| Docstrings, built with pdoc   | The API reference on GitHub Pages                | The Docs workflow fails on any pdoc warning |
| `examples/*.py`               | Runnable programs against the Sandbox            | `mypy` and `ruff` (CI); not run             |
| `docs/README.md`              | Index of all of the above and the design records | `tests/test_doc_samples.py` (links)         |

When you change behavior, update the guide that describes it and its
sample's `@runs` check; when the IR changes, regenerate and commit the
reference with the code. Docstrings in hand-written code are the API
reference, so write them for partner developers.

Build the API reference locally into `site/` (ignored by git) and open
`site/index.html`:

```sh
uv run python -W error::UserWarning -m pdoc --docformat google \
  --output-directory site teachmehipaa teachmehipaa.types teachmehipaa.resources
```

`-W error::UserWarning` turns pdoc's warnings, such as an annotation it
can't resolve, into failures, as in CI. `uv run python -m pdoc
teachmehipaa teachmehipaa.types teachmehipaa.resources` serves it with live
reload instead.

`.github/workflows/docs.yml` builds the reference on every push and pull
request and uploads it as a Pages artifact. On `main` it also deploys it to
GitHub Pages, at <https://teachmehipaa.github.io/teachmehipaa-python/>.
**Pages must be enabled once** (Nick): in the repository's Settings >
Pages, set the source to "GitHub Actions". Until then the deploy job
fails, and the README's API reference link doesn't resolve.

## Releasing

Releases go out from `.github/workflows/release.yml`, which runs only when
dispatched by hand. A run with `publish` unchecked (the default) runs the
generated-code check, lint, format, type checks, unit, README and contract
tests, `uv build` and `twine check`, lists the wheel's files and keeps the
built files as the `dist` artifact. It publishes nothing. With `publish`
checked, a second job in the `pypi` environment uploads exactly those files
with `pypa/gh-action-pypi-publish` through PyPI trusted publishing (OIDC; no
PyPI token is stored in the repository).

`pyproject.toml` carries the classifier `Private :: Do Not Upload` until
launch. PyPI rejects any upload with a `Private ::` classifier, so a
`publish` run fails at the upload even if dispatched by mistake. This is the
Python equivalent of npm's `"private": true`.

To ship (Nick):

1. On PyPI, add a trusted publisher for the `teachmehipaa` project (a
   "pending publisher" if the project doesn't exist yet): owner
   `TeachMeHIPAA`, repository `teachmehipaa-python`, workflow `release.yml`,
   environment `pypi`.
2. In GitHub, create the `pypi` environment under Settings > Environments,
   with yourself as a required reviewer.
3. In one PR: remove the `Private :: Do Not Upload` classifier, set
   `__version__` in `src/teachmehipaa/_version.py` (1.0.0 for the first
   release), move the CHANGELOG's Unreleased entry under that version with
   the date, and update the pre-release notes and install commands in the
   README and `docs/guides/quickstart.md`.
4. After it merges, dispatch **Release** on `main` once without `publish` and
   check the listed wheel files, then again with `publish` checked and
   approve the `pypi` deployment.
5. Tag the release commit `v<version>` and create a GitHub release from the
   CHANGELOG entry.
